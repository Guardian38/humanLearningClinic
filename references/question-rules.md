# 문제 작성 원칙

## 1. 모든 과목 공통 (고정)

1. **혼자 풀린다.** 문제는 다른 문제나 예제의 조건에 기대지 않는다. "위 문제", "앞의 예제", "같은 조건에서", "교재 정리 2-1에서" 같은 표현 대신 필요한 수치와 조건을 문제 안에 모두 적는다.
2. **강의에 있는 용어만 쓴다.** 슬라이드·노트에 없는 이름을 만들어 붙이지 않는다(예: 슬라이드가 기호와 식 번호로만 부르는 것을 "오류 신호"라고 이름 붙이지 않는다). 확실하지 않으면 강의 자료에서 그 용어를 찾아본다.
3. **계산은 정수로 끝난다.** 중간값과 답이 정수(또는 아주 간단한 분수)가 되도록 수치를 고른다. 계산 정답은 코드(sympy 등)로 검증한다. 단, **강의 슬라이드에 나온 예제 값은 바꾸지 않는다**(시험에 그대로 나올 수 있다). 새로 만드는 문제에만 정수 규칙을 적용한다.
4. **정답이 하나로 정해진다.** 강의 노트만으로 정답이 하나로 확정되어야 한다. 객관식 오답 보기는 흔한 오해에서 나온 그럴듯한 것으로 하고, 정답 위치를 섞는다.
5. **해설은 왜를 설명한다.** 정답인 이유와, 매력적인 오답이 왜 틀렸는지(어떤 착각에서 나오는지)를 쓴다.
5-1. **서술형은 근거 하나면 맞다.** 맞는 설명이 여러 갈래(둘이든 셋 이상이든)인 문제는 모범 답안(`a`)에 한 갈래만 쓰고, 나머지는 갈래마다 하나씩 `alts`에 둔다(개수 제한 없음). 모범 답안이나 "채점 요소"에 여러 갈래를 함께 적으면 Claude가 모두 요구하므로 섞지 않는다. 채점 요소에 대안이 있으면 "A 또는 B 또는 C"처럼 적는다. `alts`에 없는 갈래라도 강의 노트로 맞으면 엔진이 인정한다(`alts`는 대표적인 것만 적으면 된다). 강의 정리를 인용하는 답과 그 정리를 다시 보이는 답은 서로 다른 갈래다. 다른 갈래를 따로 연습시키려면 "○○를 이용해 설명하시오"처럼 그 근거를 요구하는 문제를 새로 만든다.
6. **수정 문제는 간격을 두고 다시 낸다.** (엔진이 처리: 정답이 바뀐 수정 후 다른 문제 5개 뒤) 단, 이의 제기로 학생 답안을 맞게 재채점했고 채점 기준이 크게 바뀌지 않았으면 다시 내지 않는다. 이미 맞힌 문제를 또 푸는 것은 시간 낭비다.

## 2. 과목마다 평가해서 정할 것

자료를 읽고 아래에 답한 결과를 `profile.genRules`, `profile.gradeRules`, 개념 노트, 문제 구성에 반영한다. **자료로 확인되지 않는 항목(시험 형식, 문제 형식 비율, 채점 기준, 세션 길이)은 SKILL.md 1절 4번대로 사용자에게 묻는다.**

표의 예시 열은 그 과목에서 사용자와 정한 결과를 보여 주는 것일 뿐 기본값이 아니다. 새 과목에 그대로 옮기지 않는다.

| 질문 | 예: 선형대수 | 예: 기계학습 |
|---|---|---|
| 시험 형식은? (문항 수, 시간, 형식) — 사용자에게 묻는다 | 1시간 서술형 7문제 (교수 공지) | 미정 |
| 시험이 주로 묻는 것은? (원리 이해 / 계산 / 증명 / 용어·사실) | 법칙을 알면 빨리 끝나는 계산, 짧은 증명 | 원리 이해, 간단한 계산 |
| 문제 형식 비율은? | 단답형·서술형 80% 이상, 객관식은 성질 구분용 20% 이하 | 객관식 중심, 서술형 일부 |
| 문제 하나에 걸리는 시간과 세션 속도는? | 오래 걸림 → 적게 풀고 풀이를 깊게(`cycle` 8, `sessionGoal` 6, 풀이 제출·힌트) | 짧음 → 기본값(`cycle` 5) |
| 종이 풀이(사진)가 필요한 문제는? | 3단계 넘는 계산만 `work: "photo"`, 연속 5문제 중 2개 이하 | 없음 |
| 암기형 문제는? | 연도 등은 금지 | 데이터셋 크기·연도·인명·식 번호 금지 |
| 계산 규모는? | 3×3 이하, 한 자리 정수 | 손계산 몇 줄 |
| 아직 안 배운 개념(쓰면 안 되는 것)은? | 벡터공간, 랭크, 고유값 … | 이후 주차 내용 |
| 표기 규칙은? | \|A\|, M_ij, A_ij, adj A, E₁/E₂/E₃ | 슬라이드 기호(δ, η, 식 번호) |
| 서술형 채점 기준은? | 쓴 성질과 순서, 근거 없으면 partial | 핵심 요소 포함 여부 |
| 그림이 필요한가? | 넓이·부피 정도 | 구조도, 그래프 |
| AI가 검산할 도구가 필요한가? | `matrix` | 없음 |
| 코드를 다루나? 언어와 실행기는? (`profile.code`) | 없음 | 없음 (예: 알고리즘이면 `{"lang": "python", "run": "pyodide"}`, C·Java면 `run` 없이 색칠만) |
| 코드 문제는 무엇을 묻나? (출력 맞히기 / 코드 작성 / 오류 찾기) | — | — |

과목이 암기 위주라면(예: 역사, 생물 분류) 1절의 원칙은 그대로 두고 "단순 암기 금지"를 프로필에서 빼되, 맥락이나 관계를 묻는 문제를 섞는다.

## 3. 사용자가 싫어한 것 (이전 이의 제기에서)

- 데이터셋의 샘플 수·특징 수처럼 이해와 상관없는 숫자 암기
- 다른 문제의 조건이 있어야 풀리는 문제
- 강의에 없는 용어(예: "오류 신호", "책임")를 정답 근거로 쓰는 해설
- 한 단어(예: "수용장")에 집착하는 모범 답안. 강의가 열거하는 항목을 고르게 담는다
- 조건이 애매한 문장("100개를 10칸으로 나눈다"). 무엇을 몇 개 고르는지 풀어 쓴다
- 이의 검토 직후 같은 문제를 바로 다시 푸는 것
- 계산 과목에서 객관식 위주로 많이 푸는 것. 문제 수보다 풀이 하나의 정보(어느 단계에서, 왜 틀렸는지)를 중시한다
- 사진 풀이가 연달아 나오는 것(5문제 중 2개 이하)
- 여러 가지로 설명할 수 있는 서술형에서 하나만 썼다고 감점하는 것. 예: 여인수 성질($i\neq j$이면 0)을 바르게 인용했는데 "같은 행이 두 개라 0"이라는 설명이 없다고 부분 점수를 준 것
- "○○를 하나하나 구하지 말고"처럼 무엇을 금지하는지 애매한 조건. 허용되는 것과 금지되는 것을 분명히 쓴다
